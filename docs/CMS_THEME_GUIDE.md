# CMS 深色模式使用教程

## 用户能够做什么

登录 CMS 后，点击顶部工具栏的“深色模式”可立即切换为深色界面；再次点击“浅色模式”即可恢复。
手机窄屏上按钮只显示太阳或月亮图标，可通过屏幕阅读器标签辨认当前可执行的切换动作。

选择保存在当前浏览器的 `vinci-theme` 本地偏好中，刷新 CMS、重新打开网站或进入官网页面时
继续生效。没有保存过选择时，页面使用操作系统的亮色或深色偏好。

## 页面和 API 行为

按钮会切换根元素的 `data-theme="light"` / `data-theme="dark"`，页面继续复用现有颜色 token。
按钮文字、提示和 `aria-label` 显示下一步动作，`aria-pressed` 表示当前是否为深色模式。
浅色模式同时覆盖 CMS 侧栏、导航、用户区和工作台欢迎卡；这些区域不会继续保留固定黑色背景。
未登录的 `/cms/login` 页面也提供主题按钮，并适配背景、说明区、登录卡片和表单控件；选择与登录后的 CMS 共用 `vinci-theme` 本地存储项。
登录页浅色主题使用分区半透明蒙层：顶部保持文字可读性，下半部保留团队背景照片的色彩和细节。
浅色主题的主标语使用深色标题与实心青色强调，不复用仅适合深色背景的空心白字；能力列表保持轻量分栏，不以整块白卡遮挡照片。
登录卡片使用冷灰绿色表面而非纯白，并通过更深的输入框底色、边框和辅助文字建立可辨识的表单层级。
本功能没有新增 API，请求和响应契约均不改变。

## 权限、安全和异常情况

所有已登录 CMS 用户均可切换主题，不要求管理员角色。偏好只保存在浏览器，不包含账号或内容
数据，也不会进入 PostgreSQL、Cookie、日志或审计。浏览器拒绝本地存储时，当前页面仍会完成
切换；刷新后回到操作系统偏好。禁用 JavaScript 时仍由 CSS 的系统配色规则选择主题。

## 明确不需要实现的内容

- 不提供账号级或跨设备主题同步，也不新增除亮色、深色之外的主题。
- 不新增数据库表、字段、Migration、API、依赖或环境变量。
- 不改变草稿、Revision、审核、发布、导出和 Markdown 预览。
- 不恢复代码仓库 `content/`，不引入 Nuxt Content，不修改 Wiki 拼音路径或章节逻辑。

## 本地验证与回滚

运行 `npm run test:cms`、`npm run typecheck` 和 `npm run build`。浏览器人工检查时分别在宽屏和
窄屏切换主题并刷新，确认偏好保留、文字/图标更新且键盘焦点清晰。实现只有前端布局、样式和
浏览器偏好；回滚使用普通 `git revert <commit>`，不需要数据库 down migration。
