# CMS 文章编辑器使用与扩展教程

## 1. 适用场景和前置条件

本教程适用于新闻和 Wiki 草稿编辑。使用者必须先登录 CMS，并取得当前草稿的编辑锁；
普通成员只能编辑自己有权限的草稿，审核、发布和管理员接管仍沿用现有权限模型。

正文保存在 PostgreSQL 草稿中。编辑器不会读取代码仓库 `content/`，也不会在切换模式时
写独立内容仓库。正式发布仍创建数据库 Revision 和导出 Outbox。

粘贴、拖入或选择的图片会转换为 WebP，并按
`<prefix>/<UTC年>/<UTC月>/<draftId>/<Unix毫秒>-<内容哈希前8位>.webp` 上传。仓库静态
图片和视频不使用该草稿目录；其转换与手动上传流程见 `docs/STATIC_MEDIA_MIGRATION.md`。

## 2. 富文本模式

1. 打开草稿后选择“富文本”。页面使用单栏正文画布，文章信息放在独立弹层中，不挤占正文。
2. 选中文字可使用浮动工具栏；顶部固定工具栏用于标题、格式、列表、表格等操作。
3. 在空段落输入 `/` 可打开斜杠菜单。菜单中的“Vinci 内容组件”来自系统组件注册表。
4. 选择、拖入或粘贴图片均调用原有媒体上传 API。上传成功后在当前光标处插入 Markdown。
5. HTML、Vue/MDC、模板指令及其他扩展语法不在富文本中执行或转换。它们显示为受保护的
   普通文本/占位区域，序列化时恢复原始源码。

编辑器第一次进入富文本时会使用正式 `VinciMarkdownRenderer` 的 Comark 管线核对往返前后的
最终网页渲染树，并逐项检查 HTML、Vue/MDC 和模板扩展原文。裸链接、列表标记等不影响最终
网页的等价规范化可以进入富文本；若网页效果或受保护源码会变化，页面恢复进入前的原文并
退回源码模式。旧文章中不规范且会改变展示含义的 Markdown 应在源码模式修正后再进入富文本。

## 3. Markdown 源码和发布效果

桌面端选择“Markdown 源码与预览”后：

- 左栏是同一份草稿正文的 CodeMirror 6 编辑器；
- 右栏实时使用正式网页的 `VinciMarkdownRenderer`、Comark 插件、代码高亮、文章 CSS 和
  系统组件映射；
- Wiki 右栏与正式 Wiki 页面复用同一标题编号算法，包含历史文章的标题跳级兼容行为；
- 左栏和右栏按文档进度双向同步；最近由用户主动滚动的一侧驱动另一侧。程序产生的滚动事件
  会被抑制，不会形成循环或抢夺滚动控制；
- 编辑导致预览高度变化时，系统按已记录的源码进度恢复右栏位置，不回到顶部。

屏幕宽度不超过 900px 时，双栏变为“源码 / 发布效果”切换。两个面板保持挂载，切换不会
重建 CodeMirror、丢失撤销历史或重置已记录的滚动进度。CodeMirror 初始化失败时会显示原生
`textarea` 回退编辑器。

## 4. 网站登记内容组件

当前登记四类组件：提示框、参数卡、视频和下载卡片。可从富文本固定工具栏、选区工具栏、
斜杠菜单或页面“内容组件”面板插入。组件在数据库和内容快照中始终是可读的 Comark/MDC
源码，例如：

```markdown
::vinci-alert{tone="warning" title="注意"}
请先断开设备电源。
::
```

“本文已插入的组件”会列出系统能够识别的组件。点击项目可直接编辑整段源码中的属性和正文；
保存时只替换该范围，不格式化文章其他内容。起始标签被改成其他组件时会拒绝保存，原文保持
不变。无法识别的组件不会出现在管理列表中，也不会被自动删除或重写。

开发者新增组件时应同时完成：

1. 在 `shared/utils/vinci-content-components.ts` 登记稳定标签、中文说明和默认 Markdown；
2. 在 `app/components/markdown/` 实现无副作用、支持 SSR 的 Vue 展示组件；
3. 在 `VinciMarkdownRenderer` 的组件表登记同一个标签；
4. 在 `wiki.css` 增加正式网页和预览共用的样式；
5. 为 AST、SSR/组件映射、富文本保护和未知语法保真增加测试。

组件属性不得自行执行字符串形式 JavaScript。视频和下载组件只接受站内或 HTTP(S) 地址。

## 5. HTML、iframe 和安全边界

Markdown 源码、数据库 Revision 和内容导出保留普通 HTML、iframe、Vue/MDC 及未知扩展原文。
最终预览和正式网页允许 Comark 正常渲染这些内容。渲染前只实施直接执行脚本所需的最小边界：

- `script` 标签变成可见的安全代码提示；
- `onclick`、`onload` 等 `on*` 属性以及 `srcdoc` 被移除；
- `javascript:`、`vbscript:` 和可执行 `data:` URL 被移除；
- 其他普通标签、属性、HTTPS iframe 和系统登记组件保留。

这个处理只影响网页渲染树，不会回写或清理数据库中的 Markdown。识别失败时必须保留原文；
发布前仍应由审核者检查高级 HTML 和组件参数。

## 6. 验收标准

### 6.1 用户能够做什么

- 在单栏富文本画布中编辑普通 Markdown，使用扩展工具栏和 `/` 菜单插入内容。
- 在桌面双栏中编辑源码并实时查看发布效果，在移动端切换源码和预览。
- 主动滚动源码或发布效果时，另一侧同步到相同文档进度。
- 插入、定位并修改提示框、参数卡、视频和下载卡片的属性或正文。
- 在三种展示状态间切换、保存、刷新后继续编辑，原始 HTML/MDC/未知语法仍完整。

### 6.2 页面/API 应显示或返回什么

- 富文本模式不显示并排预览；源码桌面模式同时显示 CodeMirror 和发布效果。
- 发布效果与新闻、Wiki、成员正式页面共用 `VinciMarkdownRenderer` 和组件映射。
- 自动保存、手动保存、锁状态、上传进度及错误继续使用现有页面/API 契约；本功能不新增 API。
- 表格、代码、标题、图片、iframe 和登记组件在预览与正式网页中使用相同正文样式。
- CMS 正式文章详情在数据库权威模式直接读取当前 Revision 的已解析正文和 Frontmatter；接口
  异常显示真实状态，不再统一伪装成“文章不存在”。

### 6.3 权限、安全和异常情况

- 没有有效编辑锁时正文、组件编辑和图片插入均只读；现有 CSRF、Origin 和角色校验不变。
- `script`、事件属性和可执行 URL 不能在预览或正式网页执行；普通 HTML/iframe 可渲染。
- CodeMirror 失败时回退 `textarea`；富文本往返失败时恢复原文并退回源码模式。
- 未识别组件、模板 token 或扩展语法保留原文，不做自动修复、删除或批量格式化。

### 6.4 明确不需要实现的内容

- 不新增数据库表、字段或 Migration，不改变草稿、Revision、审核、发布和导出数据模型。
- 不恢复代码仓库 `content/`，不重新引入 Nuxt Content。
- 不实现任意第三方组件市场、脚本执行、复杂 HTML allowlist 或 iframe 域名管理后台。
- 不修改 Wiki 拼音路径、章节排序和导航模块。
- 不部署、不 SSH、不修改生产数据或生产服务。

## 7. 本地验证、失败处理和回滚

不需要数据库的定向验证：

```bash
npx vitest run tests/cms-editor-modes.test.ts
npm run typecheck
npm run build
git diff --check
```

完整 CMS 回归若需要 PostgreSQL，只能提供名称明确含 `test` 且与应用数据库不同的
`TEST_DATABASE_URL`。全量旧 Markdown 兼容测试只能显式使用独立内容仓库 snapshot，不能把
snapshot 放进普通 build。

验证失败时保留草稿原文、浏览器控制台和 Network 记录；不要通过格式化或删除未知语法来让
测试通过。代码回滚使用普通 `git revert <commit>`，本功能没有 Migration down 或数据回滚。
