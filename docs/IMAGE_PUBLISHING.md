# 应用镜像发布与腾讯云补传

主分支每次 Push 按以下顺序发布，所有镜像均使用完整的 40 位 Commit SHA 标签：

1. `verify` 完成测试、类型检查、生产构建和 HTTP 验证。
2. `build-runtime`、`build-operations` 分别构建一次，发布到 GHCR，并输出镜像摘要。
3. `sync-tcr-runtime`、`sync-tcr-operations` 各自依赖对应构建，先用 Skopeo 将 GHCR 中的固定摘要完整下载到任务临时 OCI 目录并校验，再从本地上传腾讯云。

应用镜像为 `ghcr.io/sdutvinci/sdutvinci_web` 与
`ccr.ccs.tencentyun.com/sdutvinci/sdutvinci_web`；运维镜像在仓库名后加 `-ops`。
同步包含完整镜像索引和所有平台，保留摘要，并从目标仓库读取清单再次验证一致。

同一分支的新 Push 会取消旧一轮检查、构建和同步。不同分支互不影响。
PR 只检查和构建，不登录发布仓库、不上传镜像。

## 超时和失败行为

- 检查、每个 GHCR 构建任务最多 30 分钟。
- 单次复制与校验最多 60 分钟，覆盖源清单解析、复制和目标校验。
- 最多尝试 3 次（首次加 2 次重试），重试前分别等待 30 秒、60 秒。
- 每次尝试都有独立的 60 分钟预算，3 次累计最多 180 分钟；不会按前一次的剩余时间缩短后续尝试。
- Actions 复制步骤上限为 185 分钟，为重试等待和进程清理预留时间；整个任务上限为 200 分钟，另外包含安装工具、登录等准备工作。
- 认证、权限、源镜像不存在、引用格式和摘要不一致等确定性错误直接失败；其他传输错误和超时有限重试。
- 腾讯云失败会显示独立同步任务失败，不掩盖错误，也不重新构建 GHCR 镜像。

下载和上传分两个阶段执行，日志分别显示开始、完成、耗时和失败阶段。下载完成后，临时 OCI 目录
保留到本轮任务结束；上传失败重试时直接复用已校验的本地镜像，不再访问 GHCR 下载镜像层。
上传使用固定版本并校验安装包 SHA-256 的 regctl；大于 8 MiB 的镜像层按 8 MiB 分块上传，
最多 2 个并发请求。分块请求失败时在本次上传内重试对应块，仍受单次 60 分钟上限约束。
腾讯云上传进程单独使用 HTTP/1.1 作为兼容方案；HTTPS 和证书校验保持开启，GHCR 下载继续使用默认协议。
本机到同一仓库的小流量对比用于选择这一兼容方案，不能据此保证 CI 上传速度。
每个同步任务在登录正式仓库前，先对隔离的本地测试仓库注入一次断连，验证重传当前块、复用已完成块，
且完整多平台索引摘要保持一致。

整轮重试会检查并复用腾讯云仓库中已经完整保存的镜像层；整轮超时终止后，尚未完成的镜像层可能需要重新上传，
不保证跨进程的字节级断点续传。临时目录在任务退出或取消时清理，不跨任务缓存，也不作为 Actions Artifact 上传。

下载、上传在执行同步任务的 Actions 机器上进行，仍需访问 GHCR 和腾讯云。先落盘再上传可避免
慢速上传阻塞 GHCR 下载流并引发长连接中断；持续超时应按日志中的失败阶段进一步排查链路和仓库响应。

## 按原 SHA 单独补传

前提是目标版本已经通过正式检查并发布到 GHCR。手动入口只接受 `origin/main` 历史中的完整 Commit。

在 GitHub 仓库的 **Actions → Sync published GHCR image to Tencent Cloud → Run workflow** 中：

1. 选择 `main` 分支。
2. `commit` 填需要补传的完整 40 位 Commit SHA。
3. `image` 选择 `runtime` 或 `operations`，只补传需要的镜像；两者均失败时分别运行。

手动入口使用 main 当前的同步脚本，从指定 SHA 标签解析并锁定源摘要，后续尝试一直复制这个摘要。
它不执行测试、编译或 Docker 构建，不产生新代码版本。若源镜像不存在，任务直接失败。
原任务页面的 **Re-run failed jobs** 也可以重跑失败的独立同步任务。

认证继续使用已有仓库 Secrets：`TCR_USERNAME`、`TCR_PASSWORD`；GHCR 使用 Actions 的
`GITHUB_TOKEN`，同步任务只授予 `packages: read`。凭据由登录步骤保存，不作为复制命令参数。

## 服务器更新

服务器的 `APP_IMAGE` 和 `APP_OPS_IMAGE` 决定从哪个仓库拉取；本次流程修改不会覆盖服务器配置。
自动部署仍要求配置仓库内的应用、运维镜像都具有相同的目标 SHA，才会开始蓝绿更新。
使用腾讯云的服务器等待两份同步成功；同步失败时继续运行原版本。

因此，GHCR 构建成功、腾讯云同步成功、服务器已更新是三个不同状态；上线验收需再核对线上版本与页面。
