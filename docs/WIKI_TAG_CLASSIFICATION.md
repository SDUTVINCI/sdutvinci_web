# Wiki 资料组别标签

## 1. 内容写法

Wiki 资料的组别标签只写在一级资料目录的 `index.md` Front matter：

```yaml
---
title: 示例资料
tags: [嵌入式组, 软件算法组]
---
```

合法标签固定为“机械组、嵌入式组、软件算法组、运营组、通用资料”。同一资料可以属于多个
标签；重复值会去重，并按上述固定顺序返回和展示。

只有 `wiki/<一级资料目录>/index.md` 是分类来源。章节、子目录或单文件 Wiki 中的 `tags`
即使存在也不参与分类；原始 Front matter 仍随 Revision、导出和恢复无损保存，不会因为公开
投影忽略它而改写正式内容。

以下情况统一明确归为“未分类”，不会从目录静默隐藏：

- 缺少 `tags`；
- `tags` 不是数组或数组为空；
- 数组包含非字符串、固定集合外标签或带额外空白的标签；
- 数组同时包含合法和非法值。

“未分类”是公开投影的回退分类，不是允许写入 Front matter 的第六个正式标签。

## 2. 页面行为

Wiki 首页默认选择“全部资料”。桌面端使用左侧分类导航，窄屏改为横向可滚动按钮；每项显示
文档数量。“全部资料”和每个分类都按文档计数，不按章节计数。多标签资料可在每个对应分类中
找到，因此分类数量之和可能大于文档总数。

分类筛选通过 `/wiki?tag=<标签>` 保存在 URL 中，可刷新、分享并使用浏览器前进后退。搜索与
分类同时生效。公开卡片、完整受限卡片和 Wiki 详情页均显示文档级标签；详情页标签可返回对应
分类。完整受限或部分受限文档只额外公开规范化标签，不公开受限章节标题、数量或正文。

## 3. 数据链路

标签保存在既有 `articles.frontmatter` 和不可变 `article_revisions.frontmatter` JSONB 中，
不需要独立列或 Migration。Markdown 初次导入、PR 导入、草稿、审核发布、Current Revision、
确定性内容导出、snapshot 初始化和灾难恢复都沿用完整 Front matter，不丢弃 `tags`。

公开 Wiki API 在数据库 Current Revision 中查找同一一级目录的 `index.md`，严格归一化其
`tags`，再把结果投影到该文档的全部章节。章节自身的标签不会覆盖首页标签。受限文档摘要也
返回相同规范化标签；首页 Revision 变化会进入章节详情缓存键，避免继续返回旧分类。

旧数据库不需要回填：没有标签的现有 Wiki 会立即显示为“未分类”。内容仓库新增标签后，仍需
通过既有审核发布、受控恢复或测试环境重建流程进入 PostgreSQL，前台不会在运行时读取独立内容
仓库。

### 3.1 CMS 中的主文档与章节

CMS 新建入口明确区分两种 Wiki 内容：

- “主文档”对应 `wiki/<一级资料目录>/index.md`，目录名在创建草稿时确定，可直接多选固定组别
  标签；
- “章节”必须选择一个已经发布的主文档，并填写该目录下的单个 Markdown 文件名。章节继承
  主文档分类，CMS 不提供章节标签编辑入口。

创建时确定的相对路径暂存在草稿既有 `preserved_frontmatter` JSONB 的内部字段中，审核页只读
展示该位置，正式发布使用该路径并在生成 Markdown 时移除内部字段。主文档的 `tags` 则正常进入
正式 Front matter。路径已存在正式内容或活动草稿时拒绝重复创建。

数据库仍按每个 Markdown 页面保存独立 Article/Revision，以保持版本、权限、审核、恢复和导出
粒度；CMS 文章列表按一级目录把 `index.md` 标为“主文档”，随后排列其章节并显示所属关系。这是
展示和创建模型的优化，不新增易失真的父子关系表。历史单文件 Wiki 会明确标为“旧式独立页”，
继续可读可编辑，但不能作为组别分类来源。

## 4. 本地验收

使用 `scripts/cms-local-test.sh` 管理人工环境。正在运行的旧环境不会自动重新导入独立内容仓库，
不要为了查看标签直接重建并丢失已有草稿；先确认是否允许清理，或使用名称含 `test` 的独立临时
数据库完成自动验证。

人工验收至少覆盖：

1. 全部资料和六个分类入口、计数、URL 回放及搜索组合；
2. 多标签资料能从每个对应分类找到，但“全部资料”只出现一次；
3. 无标签、空数组、非法值和混合非法值均显示“未分类”；
4. 章节自带标签不覆盖根 `index.md`；章节详情显示根标签；
5. 完整受限和部分受限资料仍保持原访问控制，并参与标签筛选；
6. 浅色、深色、桌面和窄屏无溢出，键盘可操作分类按钮。
7. CMS 可创建 `<目录>/index.md` 主文档并选择标签；章节只能关联已有主文档，列表中主文档排在
   章节之前，发布内容不包含草稿内部计划路径字段。

破坏性集成测试必须使用名称明确包含 `test`、且不同于 `vinci_cms_local_test` 的临时数据库，
结束后精确删除。完成前运行相关单元/集成测试、`npm run typecheck`、`npm run build` 和
`git diff --check`。
