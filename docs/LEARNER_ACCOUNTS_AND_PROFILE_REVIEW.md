# 学员、年度选项与本人资料修改审核

## 成员申请与公开展示

正式成员和学员共用 `/team/apply`，姓名、头像、年级等必填规则保持一致。
表单使用“特殊成员身份（可选，正式成员不要选）”，提供“指导老师”和“新学员”。
勾选“新学员”后，清空并禁用团队内职务、组内职务、参加过的赛季与顾问届次，
不再要求职务或参赛赛季。指导老师与新学员互斥。组别、学院、简介和链接仍可填写。
服务端验证学员的职务、赛季和顾问届次必须为空，不能仅依赖前端禁用。

`members.is_learner` 是明确的分类状态，默认 false。年级或空赛季不决定学员身份。
成员 Revision、Markdown 导出、内容导入与恢复保留此状态。旧的成员记录保持非学员。

`/team` 以“智能机器人创新实践基地学员”独立展示全部有效学员，不分年级，
不新增任何筛选。该板块不受正式成员区的赛季、组别或搜索筛选影响，也不重复出现在正式组员区。
学员不计入各赛季正式队员人数，仍可打开其公开个人详情。

## 年度选项

`/cms/member-options` 分别控制年级 active 和赛季 season_enabled。关联赛季允许为空。
启用年级使其出现在新申请表；开放赛季使其出现在参赛和顾问届次选项，二者独立。
选择年级只影响组别选项，不自动填写参赛赛季。

已存在的 2026 级、28 赛季配置不会被迁移覆盖，不会自动把该届全部成员设为学员或认定其参赛。
管理员可关闭 28 赛季的可选状态，同时保持 2026 级供学员申请。
既有年度记录迁移时保留原先赛季选项是否开放的效果；新增年度默认不开放赛季选项。

停用年级、赛季或移除组别只限制新增选择，不改变已有公开档案；本人修改和管理员维护时可保留
原档案中的历史值。公开新申请仍只接受启用年级和有效选项。

## 注册与权限

继续先申请成员档案、审核上线，再在 `/cms/login` 的同一注册表单认领资料并申请账号。
账号审核时依据当时有效成员档案，学员获得 reader，正式成员获得 member，管理员单独授予。
账号与档案仍是一对一，稳定账号 ID 不变。

reader 可以登录前台、使用 `/account`、阅读公开或需登录的文档、导出可读 Wiki PDF 和使用下载页。
reader 不能进入 CMS、编辑文章、操作草稿、编辑锁或进行 PR 内容导入。
CMS 页面中间件与全部正常 CMS API 都验证后台角色；会话、退出登录和 Wiki PDF 使用站点鉴权。
登录入口复用现有会话，默认回到 `/account`，携带合法站内回跳路径时回原页面。

## 本人资料修改：所有角色都需审核

`/account` 提供本人完整基础资料编辑、上传头像、修改密码和申请转正。
提交资料创建 member_proposals 待审核提案，不创建正式 Revision、不修改成员当前指针、不排队导出，
也不改变账号权限。头像上传只准备候选图片，且提交时校验上传者、所属成员与有效期。
未使用头像候选 24 小时后由定时任务清理；拒绝或撤回后清理该申请的候选图片。

每人同一时刻只有一份待审核的本人申请；可撤回重填。管理员在审核中心查看逐字段前后差异，
明确通过或填写原因拒绝。管理员自己的修改也先提交，管理员可以明确审核本人申请。
没有“管理员保存本人资料直接生效”的例外；直接编辑／上传头像／恢复自己的正式档案会拒绝，
指引其进入个人中心。管理员维护其他人的档案继续保留原有受控管理操作。

审核通过在单一事务中创建正式成员 Revision、更新投影和指针、记录审核与审计、排队内容导出。
若学员状态改变，同时同步关联账号 reader/member 权限；管理员角色不因成员分类自动授予或移除。
学员转正无需重新注册，反向转为学员收回编辑权限。

审核检查当前 Revision 与成员版本。原资料已发生变化时不应用旧提案，管理员拒绝后由本人
重新提交，或本人主动撤回重填；不静默覆盖并发修改。重复通过已应用的提案保持幂等。

## 验收

- 2026 级学员上传完整资料，无职务、赛季仍可申请并注册 reader。
- 团队筛选不影响学员板块，所有学员只出现于独立板块。
- reader 直接调用 CMS 草稿和成员管理 API 返回 403；站点资料与 PDF 接口仍可使用。
- 姓名和头像上传、转正申请在审核前不改变公开资料、Revision、导出队列或账号权限。
- 管理员本人也先提交，再明确审核自己的申请；通过后生效。
- 拒绝、撤回、重复提交和原资料并发更新都有明确处理；他人申请不能被本人撤回。
- 停用年度与赛季后，已有成员保留原值的修改仍可审核。

Migration 0029/0030 是向前扩展，不执行 down，不写生产数据库。

account-registrations.integration.test.ts、cms-auth.integration.test.ts、public-downloads.test.ts。

个人中心和共用申请表使用同一套输入框、选择卡片及禁用态样式。头像区域显眼提示必须先填写姓名；姓名为空禁用上传。提交、审核、拒绝、撤回与失败提供可关闭的浮层反馈，同时保留页面内结果说明。
